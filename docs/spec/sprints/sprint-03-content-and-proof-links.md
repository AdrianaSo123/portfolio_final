# Sprint 03: Content Quality and Proof Links

Date: 2026-04-15
Status: Planned

## Goal

Raise trust by replacing placeholders with real proof paths and sharpening project communication.

## Why this sprint exists

Current project CTAs are wired, but links and proof depth need production-quality content decisions.

## Scope

- Project card copy and CTA destination quality.
- Portfolio proof credibility improvements.

## Tasks

1. Replace placeholder `liveUrl` and `architectureUrl` values with real destinations per project.
2. For projects without a live system, keep a clear fallback label (`View GitHub`).
3. Tighten project summaries to outcome-first language.
4. Ensure each project has a clear proof statement and outcome metric where available.
5. Add any missing static assets (for example touch icons) to remove runtime 404 noise.

## Acceptance Criteria

- All 3 featured projects have accurate CTA destinations.
- Button labels match destination type.
- Project copy is concise and executive-readable.
- No avoidable static asset 404s for standard browser requests.

## Risks

- Missing public links for private projects.
- Inconsistent naming between architecture docs and repo naming.
